# 织律 · Ruleweaver

2D 横向探索建造沙盒：玩家组合规则，创造物质与行为。

**当前为 v0.17 可操作开发场景：从空背包采集材料、制作独立造物、编织规则、存读档并完成遗迹探索；新增无副作用规则预演、运行反馈，以及同一世界的下层探索。画面是简化程序化素材，不是概念图成品或正式发行。**

## 打开游戏

使用锁定的 Godot 4.6.1 导入 `godot/project.godot`，按 F6/F5 运行 `presentation/main.tscn`，或者：

```sh
/path/to/godot --path godot
```

Actions 的 `playable-windows-<commit>` 工件在原生测试之后生成自包含开发运行包：解压其中的 `Ruleweaver-v0.17-windows-x86_64-development.zip`，运行 `Start_Ruleweaver.bat`。内附官方引擎，无需另装编辑器；这是“官方引擎运行源码”的开发包，不冒称优化导出、签名安装器或 Stable Release。以对应提交的实际打包结果为准。

首次进入暂停。点击“继续探索”开始。

## 首段探索

地图有 6,000 单位环境水，角色初始没有材料或随身造物。先点击继续探索，选择 2 挖掘头顶六块石料；按 B 制作储水容器（4 石料）和便携夜灯（2 石料）。材料配方只制造载体，不枚举行为组合。可以制作多件同类物品，每件都有独立编号、水量与规则。目标仍是携灯到访右侧遗迹，然后回营地交水 500。

在背包列表选择容器，点击“选中并放置”，把容器放在水面上方的空格（例如角色附近的 `(1,-1)`），打开织律台，使用或拆改“限量吸水”草稿，点击“应用到造物”，收起织律台后让程序运行。水位下降后收回装水的容器，放灯、进入遗迹、返回营地交水。也可以直接挖开地板排水，或者手工搬水；目标不检查指定配方。

织律台编辑时世界暂停。初始结构仅为可拆改的普通规则图；“节点与连线”中可添加节点、拖动端口连线、断线、修改参数，选中节点后 Delete 删除。被引用的节点需先断线。草稿校验和预览不修改世界，“应用”才发布不可变新版本并绑定所选造物。

**F5 会把未应用草稿、选中对象、工具及完整世界共同保存。** 不完整草稿也能保存，但仍不能通过发布校验，恢复时不会执行。撤销历史与节点位置暂不持久化。世界存档保存已发布规则、身份、水量、位置、时钟、目标和角色速度。律卷导入不会自动绑定；导出已有文件须明确覆盖。新探索会清空当前未保存进度，但不会删除磁盘存档。v0.14起使用独立槽位，v0.17沿用它；没有新槽位时 F9 会明确提示载入 v0.13 旧进度，旧文件不被覆盖。损坏的新槽位不会被悄悄替换为旧进度。

## 继续探索与规则预演

完成第一次交水后，提示会切换到下层回廊。回收或再制作夜灯，挖开 `(6,1)` 附近地板，照亮并到达 `(6,2)`；再在上方储水格 `(8,1)` 放一件至少装有 1000 单位水的容器。可以复用原来的造物，不会清空规则、水量或背包。开挖后有流水时，等它流走或先手动取水再放置。

织律台“预演一拍”在隔离副本中运行候选规则和环境，显示可执行、等待、休眠或受阻原因，**不改变真实世界，也不代替应用**。世界面板还显示选中造物的上一拍结果。完成四项目标后仍可继续建造和试验。

v0.17继续使用v0.14工作区槽位。旧进度读入后保留前两项目标，F5才保存升级后的场景版本；新存档不保证旧程序能读取。详情见 `docs/GUIDED_EXPLORATION.md`。


## 自创词条与参数复用（v0.17）

在“节点与连线”中，数值/开关常量旁可填写参数英文名并点击“公开参数”；原节点和连线保留，调用方可传入不同数值。参数有类型与默认值，支持撤销和显式还原为常量。

右侧“自创词条”输入 `user:water_pump` 等ID，点击“存为词条”：把当前完整有效图发布为不可变版本，只进入库，不应用、不推进世界。选择库中某版本后“追加调用”，会生成真实call节点、执行条件和独立参数常量；可以改值或换成其他计算节点。多个词条可组合并再次保存，例如吸水＋暗处发光。现阶段封装的是完整行为图，不是任意选区提取或带返回值的通用函数。

“编辑所选副本”不会改旧版本，可撤销；再次保存获得新版本，旧调用保持原版本。“导出所选词条”能导出尚未绑定的模块及完整依赖；导入不自动绑定。库和参数化草稿沿用原存档，协议、槽位和既有规则上限不变。命名目前使用现有ASCII ID，尚没有独立中文显示名、库分类或删除界面。

## 凝水地块与高处路线（v0.17）

完成下层补给点后，回收原容器和灯。织律台起始结构新增“向上凝结地块”和“向上回收地块水”，它们是可拆改的普通节点图，不是锁定配方。每块凝水晶从容器取500单位水，成为真实地形与碰撞；回收返还相同水量，挖碎只释放环境水，不重复掉落资源。普通石块同样可以搭路。

高处目标是照亮并到达 `(0,-3)`。一种方案是在 `(0,-2)` 和 `(1,-1)` 形成台阶，再逐级跳上去。可以先把容器放在 `(1,-2)`，将凝结图的“相邻格可用”和“凝结地块”方向都改为向左，形成高一级；之后回收，在 `(1,0)` 向上凝结低一级。先清理拟放置格的残水，回收容器再起跳。也可直接用两块石头搭相同台阶，目标不检查解法。

世界总水量包括地面自由水、容器水和固体封水；材料能力由受信目录定义，玩家不能通过律卷把普通石头改成免费生成。旧v0.16存档保留已有四目标和所有资源，读取不自动授予第五目标；F5保存后场景升级v3，不保证旧程序能反向读取。界面仍是同一开发美术，有限地图，不是无限生态。

## 自动检查

Python 3.11+，标准库，无 pip 依赖：

```sh
python tools/run_checks.py --offline-only
python tools/run_checks.py --godot /path/to/godot
python tools/package_desktop.py --godot /path/to/godot --output packages
```

Windows 可使用 `Godot_v4.6.1-stable_win64_console.exe`。`python tools/install_godot.py --destination .tools/godot` 下载并校验固定官方归档。退出0为请求范围通过，1失败，2原生环境受阻；离线通过不等于引擎通过。

真实UI验收覆盖鼠标工具栏/世界点击、键盘移动、原生GraphEdit端口拖动、草稿应用、抽水途中磁盘恢复、到访遗迹和交水。测试不替代真实设备、最终美术或手感验收。完整空包路线及草稿兼容见 `docs/CRAFTING.md`；界面与当前证据见 `docs/INTERFACE.md` 和 `docs/STATUS.md`。

## 工程与许可

`runtime/` 保存唯一世界、规则、资源和存档；`presentation/` 只负责显示、编辑和调用这些服务，不维护第二份水量或库存。正式运行不依赖 Python、tests 或 scenarios。旧协议和旧路线测试继续保留。

有限场景、有限原语和全快照事务仍有规模上限，没有无限地形、多人、声音、游泳、最终美术或大世界性能结论。当前可操作不等于整款游戏已完成。
