# v0.14 · 采集、制作、编织与工作区恢复

继续既有 Godot 4.6.1 工程，不改变2D产品方向，不重做物理、库存或规则运行器。

## 实际路径

新探索为 `fresh_expedition.json`：0石料、0随身造物，营地已有公共蓄水器，世界6000单位水。采集头顶六块石料，B背包中制作容器4和灯2，再选择、放置、编织限量吸水程序。沿用湿暗遗迹目标：排水、携灯到访、返回交水500。可以挖沟或手工搬水，不要求使用指定程序。

`first_expedition.json` 保留为v0.13兼容场景，原交互测试仍明确加载它。新测试只从空包场景运行，不用旧场景冒充采集制作完成。

## 载体不是词条配方

`CreationRecipes`只定义受信材料成本、载体材料和初始容量。储水容器没有默认程序，灯的默认照明也是既有可替换规则。新增编号`creation:made_######`在世界中避让现有对象。多件同类载体不能合并水量、共享可变规则或覆盖身份。

权威路径：界面 → PlaySession受限暂停制作入口 → ExpeditionSession → WorldSession暂存扣料/创建 → 完整存档校验 → 一次提交。材料不足、未知配方、资源/对象上限、重入失败都不允许部分扣料。玩家导入律卷不能直接调用制作服务。

背包读取WorldSession的造物与堆叠材料，不维护第二份库存。列表只列随身实例；世界中造物仍可通过鼠标选择。放置、取排水、交付、编辑、显示按实际选中实例执行，不再要求固定`creation:vessel`或`creation:lamp`名字。

## 工作区存档

`rw.workspace/0.1`封装既有`rw.play/0.1`与editor：selected、tool、drafts。未发布草稿允许缺线，但必须满足有界RuleDraft结构；最多64个草稿，与实例ID对应。恢复先验证整个信封，再采用完整世界与编辑态；加载草稿不等于编译、绑定或执行。

F5保存当前打开的草稿和其他对象缓存草稿。应用才发布新规则版本。撤销/重做历史、节点画布位置不在本版保存范围内。

默认槽位`first_expedition_014`，保留旧`first_expedition_013`。F9仅在新槽位及其备份均不存在时提示旧槽位；若新槽损坏，只沿新槽备份恢复路径，不静默装载旧进度。旧`rw.play/0.1`仍能读入；旧档不凭空产生草稿，下一次F5另存新槽。

## 自动验收

新增原生测试：crafting、workspace、crafting_ui、inventory_edges。新完整路线投递实际鼠标键盘，采集六块石料、制作两物件、按列表选中、编织泵、保留缺线草稿并磁盘重载、完成遗迹和交付。全过程水量6000，材料6→0，灯/容器身份不同。独立Python检查产物中的地形差异、身份、规则、草稿、目标、材料和总水量，不复制模拟器。

实际渲染检查1440×900和1152×720；沿用已有开发UI，未把这次技术接入当成最终视觉/手感批准。截图不是概念生成图。

## 边界

没有声音、游泳、无限世界、新材料能力或大规模性能结论。当前制作是两种载体，不是完整科技树。草稿数量和快照大小有保护预算。开发包仍是官方引擎运行源码，不是优化导出或签名发行包。
