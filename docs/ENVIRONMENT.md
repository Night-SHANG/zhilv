# 环境资源与湿暗遗迹 · v0.11

这批将资源、规则、时间和探索目标一次接通，不再仅验证孤立词条接口。仍是原生无窗口技术实现，不是已经完成角色手感/画面/织律台的可玩游戏。

## 一张地图，三种方法

运行 `godot --headless --path godot --script res://scenarios/demo_expedition.gd`，同一场景执行：

| 路线 | 实际操作 | 共同结果 |
| --- | --- | --- |
| 手工搬水 | 用已有容器取水，让通道水位下降 | 搬灯进入遗迹，再回营地向储水槽交付500单位水 |
| 挖沟排水 | 挖开一格地板，让水落入更低的蓄水空间，再装水 | 同一结果，不强制玩家编程 |
| 自创规则泵 | 从空白RuleDraft建立检测水、读取水量/容量、计算限量、转移的图；发布绑定后运行 | 同一结果，完整规则保留在存档中，可复用到另一种物质 |

初始环境水6000单位，各条路线结束时“环境格+所有容器”的总量仍为6000。灌溉目前指将水交到营地槽，不代表植物生长或农业系统已实现。三条脚本是自动操作回放，核心世界系统和目标判断不识别“遗迹泵”或路线名，不直接修改最终存档来完成目标。

地形、角色网格占位、灯光开关/遮挡、搬运和创造采用同一WorldSession。没有第二套库存或为测试另造一个假世界。角色目前是两格占位及网格步进，尚无平台跳跃/重力动作。

## 水层与守恒

- 新世界格式 `rw.world/0.2` 增加water数组，每项 `{cell:[x,y], units:整数}`；每格1～1000，最多4096个水格，水不能与地形或造物重叠。角色可暂留在被淹位置，不把存档因此报废。
- `rw.world/0.1`仍按原规则读取；不能通过改成旧版本来静默丢弃水。`enable_environment`显式升级无水旧世界。
- 手工取水/倒水和规则取水/排水共用整数账本。资源不足、容量不足、距离/遮挡、地形冲突及预算失败，均保留旧状态。
- 规则移动和建造不覆盖现有水；当前位置的水可排入空格，但不凭空消失。单个造物的一组动作仍为完整事务。
- 简化流动：先自下向上处理重力，再从固定中间快照进行水平平衡；每次下落最多一格，边界是墙，不丢弃1单位余量。
- 固定排序，不依赖字典输入顺序；水平阶段预留出水量防止多方向重复花费。不是压力流体、气体、真实水力学或完整生态模拟。
- 当前每步扫描有界水格，不冒称已实现活跃区块休眠、无限世界或性能验收。借鉴Coheronia固定步元胞结构，但未直接移植它耦合原节点、浮点epsilon删除和预设反应的实现。

## 规则与时钟

新增通用原语：`neighbor_water`、`water_exists`、`water_units`、`take_environment_water`、`release_environment_water`、`is_ambient_dark`、`sub`、`min`。环境格引用与实例引用是不同类型，不能错连。

泵图限量为 `min(单步速率,水源剩余量,自身空余容量)`，没有水或装满就不产生动作。照明查询采用天光是否被顶上地形遮住，不把自身灯光作为关闭条件，以免自行闪烁。`has_light_at`采用有限半径和现有保守视线遮挡，是逻辑照明判断，不是GPU光照。

`rw.simulation/0.2`同时保存完整世界、规则、已完成步数以及clock配置（循环步数、白昼步数、暂停）。旧0.1恢复会清除时钟，不能留下上一次运行的配置。公开的昼夜状态对应刚完成的规则步，避免边界时先显示夜晚而灯还在白昼状态。

`advance_tick`先让所有规则读取同一快照，在暂存世界中按稳定实例ID提交，再执行水流；全局指令/水预算失败则整个tick不前进。造物本身的动作冲突按既有每实例事务语义报告。最后一次采用完整状态并通知观察者。它是短命候选事务，不是第二个持久世界。

`SimulationDriver`是实际Godot Node，可由物理帧驱动固定tick。长帧最多追赶4步；暂停丢弃时间积压，不作离线补算。恢复无时钟旧档后驱动器正常拒绝而不抛异常。单步可以在保持暂停的情况下执行一次。

## 探索目标与保存

`ExpeditionSession`引用同一world/runtime。目标仅检查实际世界结果：到达指定格、足够照明、浅水，以及返回营地后交付水。先后依赖明确，已完成目标锁存，走回营地不丢失“曾进入遗迹”。

`rw.expedition/0.1`保存场景ID/版本、完成列表及完整simulation。沿用既有CheckpointFiles临时校验与备份。不保存外部可执行脚本。场景版本、目标依赖、世界ID、图、时钟或水层出错时，不能覆盖正在进行的探险。

原生验收覆盖在自动泵运行中实际写磁盘并创建新会话恢复，最后状态与不中断运行逐字相同；反转初始水格排列也一致。独立Python读取最终三路线工件，检查规则内容、身份、地形修改、容量、时钟和水总账，不再用Python重写一个游戏模拟器。

## 当前边界与下一阶段

没有拖拽织律台、可操控平台角色、正式美术、GPU照明、水面绘制、游戏导出包或多人。现有地图投影继续使用原生节点，但新增水层的正式视觉仍需视觉样板。当前目标与地图是有限首段内容，不等于程序生成世界或长期成长内容完成。

技术路径现在覆盖：创作→发布→放置→改变环境→进入遗迹→搬运回用→保存继续。下一阶段应在锁定首段内容与视觉样板后将这些同一接口接入正式操作/显示，不继续扩大通用引擎或另造临时试玩版。
