# 原生受限规则图与世界执行实施计划

**Goal:** 让世界中的造物读取同一步快照，通过有类型规则图生成受限动作；共享子模块、预算和存档重载均有原生证据。
**Architecture:** 沿用 WorldSession、SnapshotCodec、InstanceStore、CheckpointFiles。新增规则图编译器与执行器，禁止任意脚本、动态宿主方法调用；规则动作与玩家操作共用世界提交边界。
**Tech Stack:** Godot 4.6.1 / GDScript；Python仅用于质量门，不成为游戏运行依赖。
**Spec:** Notion产品04、技术05 v0.8；本文件收口本轮局部前置设计。

## 本轮固定边界
- 图为纯数据DAG，动作顺序独立；支持布尔/整数/可空实体引用，节点ID与显式输入引用。
- 基础能力：常量、参数、昼夜、读取自身状态、相邻容器、存在、比较/布尔/加法、设置自身灯光、移动自身一格、从邻接容器精确转移水量、调用行为子模块。
- 子模块公开带类型参数，无返回值；禁止直接或间接递归。不承诺完整可视化编辑器或所有词条。
- 每包最多64模块，每模块最多64节点、8参数、16动作；调用深度8。每造物默认512指令、上限4096；每步总预算默认32768、上限65536。
- 每步读取同一世界快照；实体按ID、规则按ID排序。先生成计划后提交；同一造物全部动作作为一个事务。冲突按排序确定，失败不部分改变世界。
- 背包造物休眠；规则不可任意改水量、身份、归属、容量或远程对象。转移必须邻接且守恒。
- 存档信封rw.simulation/0.1包含规则包、步数和原世界；沿用已有材料/规则版本目录，旧世界协议不改。
- 第一次支持由宿主逐步传入昼夜，不实现真实昼夜计时、自然流体、事件队列或离线演化。

## Review Focus
1. 超预算在任何动作提交前拒绝；其他造物不能受半完成计划影响。
2. 相同规则换物质/参数即可复用；不按造物名称分支。
3. 缺失版本、坏端口、循环依赖、越权动作均拒绝且不替换旧规则包。
4. 库存造物停机、碰撞/角色占位和邻接限制不能被规则绕过。
5. 保存重载保留图、步数与动态状态；失败载入保留旧运行时。
