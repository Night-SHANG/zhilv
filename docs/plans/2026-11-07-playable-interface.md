# v0.13 可操作界面整批接入

> 执行：superpowers:executing-plans；先写测试并观察失败，再实现和完整回归。

**目标：** 沿用v0.12权威世界，将角色、可见地形/水/造物、中文HUD、织律台编辑/应用/分享和磁盘存读档接入同一可启动场景。
**架构：** 显示读取WorldSession，不另存世界。LoomDocument包装RuleDraft；GraphEdit只是编辑交互。所有用户副作用仍由PlaySession/RuleRuntime/CheckpointFiles负责。
**技术：** 固定Godot4.6.1，原生Control/GraphEdit/SystemFont/CanvasItem。无新第三方运行依赖，无字体文件打包。
**依据：** docs/PLATFORM.md、docs/RULES.md、Notion06视觉说明和当前对话中已展示的候选图。

## 范围与裁决

用户在视觉候选后要求“继续”，据此推进该方向的可运行实现，不标为正式审美验收通过。保留暖营地/冷洞穴、清晰地形和右侧织律台；有限形状的程序绘制素材是可运行首版，不宣称达到概念图美术精度。生成图中的里程碑数字、血条等不是需求和事实。

不改动既有存档格式/物理算法/运行器；不把已验证的图形前置重做为另一款网页游戏。无新生物、战斗、平台或多人。不合并main、发布Stable。主程序不能依赖tests目录。

## 文件职责
- presentation/loom_document.gd：草稿操作、历史、便利模板、同一编译器校验。
- presentation/loom_panel.gd：简单操作及可编辑GraphEdit；端口连线、配置、删除、预览与应用。
- presentation/world_canvas.gd：权威地形/水/主体的只读可见投影与指针映射。
- presentation/ui_theme.gd：共用颜色/控件样式/系统字体。
- presentation/play_app.gd + main.tscn：场景、输入门控、HUD、选择、导入导出、保存恢复。
- runtime/scenario_loader.gd：从受信内容装配现有世界和运行时，Routes与主程序共用。
- tests/test_interface.gd：实际原生控件/事件、编辑器、文件和世界动作验收。

## 必须验证的边界
1. UI点击不会穿透到世界；织律台/文件对话框打开时冻结并清空角色输入，关闭保留原暂停状态。
2. 草稿错误/取消/预览不改变运行世界；应用只更新选中对象，保留身份与资源；版本递增。
3. 指针格坐标在不同布局、缩放、窗口尺寸下一致，地图和角色状态来自同一世界。
4. 存档/坏存档/备份恢复有明确结果，任何导入不自动绑定；不静默覆盖导出文件。
5. 实机截图仅来自运行场景；无渲染/GPU/交互证据时不可称视觉或手感完成。
