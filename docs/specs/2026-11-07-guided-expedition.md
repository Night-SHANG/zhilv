# v0.15 首次引导、无副作用规则预演与下层回廊

## 用户目标与选型
保持Godot4.6.1原生2D、单一权威世界；用户已授权成组推进而非逐细节确认。当前短板：玩家不知道造物为何不运行；第一组目标完成后缺少继续使用造物的场景。复用RuleCompiler/Evaluator、快照事务、ExpeditionSession与现有HUD，不另加模拟器或另做新游戏。

备选：直接堆更多词条（不能解决可理解性）；重做UI/新增地图平台（重复工作且未经视觉收口）；在同一世界增加反馈、现有素材可达的回廊目标。采用第三项，保持布局与开发美术不变。

## 范围
1. 规则执行产生有界、只读、逐造物结果；显示上一步的成功/等待/失败原因。无权限扩大，不持久化诊断缓存。
2. 织律台“预演一拍”在隔离候选世界运行完整原生规则/水步，不改变当前世界、规则库、时间、任务、草稿或已发布版本；报告选中造物结果，清楚区分预演与应用。背包中造物显示休眠，不假装放入世界。
3. 根据真实目标/库存状态计算下一步提示，不强制某一种解法，不给程序静默补料或完成任务。
4. 同一fresh场景追加下层回廊：首次交水之后可挖开脚下、复用照明工具到访下层格(6,2)，再把至少1000水的任意容器放到(8,2)建立储水点。通用supply目标按世界结果，不检查特定造物ID/程序。旧前两项及6000总水不变，不新增资源。
5. 数据声明的append-only目标版本兼容：新定义v2接受v1仅有已知前缀目标的存档，保存后升级v2；拒绝旧版本声称完成新增目标。旧场景仍v1，旧自动流程保留。

## 验收
- 所有原有测试重跑，不混算；记录每个真实新增失败再实现。
- 阻挡/条件为假/背包休眠/争抢水/坏草稿/总预算失败，反馈不能把未提交变更说成成功。
- 预演前后权威检查点和规则库逐字一致，成功与失败都如此。
- 原生输入完成空包→制作→原遗迹→交水→下层回廊→复用同一容器供水，保存恢复不刷任务或水。
- 旧v1读入v2，旧档带新目标拒绝；不覆写旧存档。
- 1440x900及1152x720实际截图检查，不把它当最终视觉认可。

## 非目标
无限地形、多人、离线补算、任意脚本、完整生态、最终音美术、性能承诺；不扩大物质注册或规则语言。不改变第三方许可。main与Stable不更新。
