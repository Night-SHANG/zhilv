# 原生平台操控接入设计

基线为仓库bef633d（源码交接f4295ed），而不是聊天中未提交且语义不同的v0.11附件。保留既有三解遗迹、规则、库存、守恒及全部旧测试。用户已授权连续自主实施；本轮不等待普通技术选择。

## 目标与非目标

将Godot原生CharacterBody2D、TileMapLayer碰撞和输入事件接到同一个WorldSession/ExpeditionSession，使左右移动、落地、跳跃、挖掘后失去支撑、搬运和暂停/恢复不再只依赖网格回放。无精灵、HUD、UI布局、正式画面或发行；视觉实现仍须样板确认。不承诺手感、GPU或大世界性能。

## 采用与取舍

采用引擎CharacterBody2D.move_and_slide及TileMapLayer碰撞，不自造平台物理求解器。不采用仅移动精灵的第二世界；它会让规则和放置检查漏掉半格身体。不用“格点跳跃+插值”冒称连续物理。

世界协议0.3增加固定尺寸身体的整数亚格脚点，1024单位/格；宽640、高1792单位。actor.cell是脚点派生的交互坐标，身体覆盖的全部格用于挖建、规则移动及存档碰撞验证。0.1/0.2保持读取和旧语义。角色速度留在play检查点，输入不持久化。

碰撞层复用TerrainProjection并隐藏，只负责已装载窗口；16像素/格与世界原点分离。角色移动经引擎碰撞，再由权威世界校验，失败恢复；不允许任意位置穿墙。深水继续沿用当前不可进入的规则（允许从已淹没格离开），游泳/淹水受伤后置。

PlaySession统一输入、角色帧与已有固定模拟驱动；暂停冻结二者并清空按键，失焦进入暂停，不追赶离线时间。规则编辑入口暂只控制输入开关，不制作未经确认的UI。交互仍走已有距离/遮挡/资源校验。

## 通过条件

真实物理帧里验证落地、按键移动、跳跃、墙顶/头部碰撞、挖地后下落、半格身体防嵌入、规则移动占位；统一暂停和单步；磁盘恢复角色姿态、速度、规则、资源和进度；坏存档/重入不部分提交；旧三解回放不退化。只认可实际执行结果。

参考：Godot官方CharacterBody2D与TileMapLayer文档、既有TerrainProjection、SimulationDriver、CheckpointFiles。实现者复查与自动测试不称独立审计。
